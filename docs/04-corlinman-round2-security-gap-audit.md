# corlinman 第二轮安全差距审计

日期：2026-07-23
研究对象：`sweetcornna/corlinman`
核验快照：`v1.36.1` / `2d51c5a05d13601bc5467fc0c68ab4768344f29c`

## 结论

维持 ADR-0001：第一阶段自研窄核心，按需复用 corlinman 的独立设计、测试和 MIT 代码，不直接分叉整个仓库。

corlinman 已经覆盖 QQ、身份、人格、记忆、工具、审批、后台和部署，是本项目最重要的参考基线。但它仍不是“直接安装后就天然满足主人最高权限与抗记忆投毒”的成品。尤其是人格 owner ACL 和新记忆内核的后台治理，还需要本项目自己补齐。

## 已确认可借鉴的成熟能力

### QQ

- NapCat + OneBot v11 接收私聊、群聊和多模态消息。
- 事件包含真实 `user_id`、`group_id`、`self_id`，可用于确定性身份判断。
- 群白名单是硬门，@ 和命令不能绕过。
- 默认群策略为 `mention_or_keyword`，并有冷却、限流、主动发言预算和紧急静音。
- v1.36.1 可从 OneBot 事件自动识别当前登录 QQ，支持运行中切换账号。

### 身份

- 外部通道账号映射为内部 UserId。
- 跨通道身份合并需要短时验证短语或后台操作，不依赖昵称等模糊信号。
- 新记忆内核按 tenant、用户、persona 强制过滤，并有零跨域泄漏的黄金测试。

### 记忆

- 热路径只写 observation，不把每条聊天直接变成长记忆。
- 休眠期 `memory.reconcile` 执行抽取、脱敏、风险分类、去重与替代。
- 记忆项包含来源、风险、置信度、重要度、信任度和双时间有效区间。
- 更新通过失效旧事实并创建新事实完成，而不是覆盖历史。
- 正式召回可融合 FTS5/BM25 与向量余弦，并记录 recall ledger。
- 高风险项不会进入 ranked recall；召回内容被标记为非可信数据而非命令。

### 人格与工具

- Persona 的稳定 system prompt 与 mood、fatigue、近期话题、生活状态分离。
- 工具权限可以按 tool、参数、模型、session、user_id 匹配，并支持 allow、deny、ask、log。
- 高风险工具可进入人工审批，代码执行可放入隔离环境。

## 与本项目目标不一致的关键缺口

### 1. 命令管理员兼容逻辑可能 fail-open

上游 `CORLINMAN_COMMAND_ADMINS` 未配置或为空时，为兼容旧部署会把调用者视为管理员。本项目必须反向实现：

- owner 未配置时，所有高权限命令和写操作失败；
- owner 只能由部署 secrets 或后台二次确认绑定；
- 聊天、记忆和模型输出永远不能修改 owner。

### 2. Persona 的 `owner_user_id` 尚未形成强制 ACL

上游已在 persona 表加入 `owner_user_id`，但设计文档明确说明当前是未来字段，暂不做授权强制。Persona 的 system prompt 又会作为 system message 注入每轮聊天，因此本项目必须增加：

- constitution/style 的版本与发布状态；
- owner-only 创建、修改、发布和回滚；
- 普通聊天只能提出 persona change proposal；
- 当前生效版本使用只读快照，不能被运行时状态覆盖。

### 3. 新统一记忆内核缺少完整后台治理面

上游内核已有 `invalidate_item()`，但当前 `/admin/memory/*` 主要只有旧 RAG 衰减重置；没有围绕 `mk_items` 的完整搜索、来源查看、隔离、失效、恢复和替代链 UI。

本项目 Phase 3 必须把 Memory Control Plane 当成核心功能，而非后续美化：

- 按人、群、persona、风险、状态和来源检索；
- 查看原始证据与本轮召回账本；
- 编辑时创建新版本并失效旧版本；
- 支持隔离、恢复、批量撤销和按来源清除；
- 所有操作写不可抵赖的审计记录。

### 4. “低信任”不能替代“无权修改”

上游 reconcile 会把部分冲突候选作为低信任事实保存，再交给信任循环处理。这适合一般事实演进，但不适合 owner、权限和 self core。

本项目必须在数据模型层禁止聊天生成以下类型：

- owner 身份与角色权限；
- persona constitution；
- 密钥、审批规则和工具能力边界；
- “谁可以命令智能体”的定义。

这类内容即使重复一万次，也只能作为攻击事件或待审核提案，不能成为可召回事实。

### 5. 默认 shadow 不等于功能已经启用

v1.29 的记忆内核默认处于 shadow；大量新行为也由配置门控制。评估上游时必须区分“代码存在”“默认启用”“生产验证”三种状态，不能只看 README 或分支名。

## 本项目必须固定的优先级

1. 不可变安全策略与 owner ACL；
2. 当前会话的确定性身份、群和权限结果；
3. 已发布的人格 constitution/style；
4. 当前任务与显式承诺；
5. 经过审核的长期记忆；
6. 原始聊天、网页、工具输出等非可信内容。

低层内容不得改写高层内容。模型只能在这个优先级内生成语言，不能自行重新排序。

## Phase 1 之前的硬性门槛

- 使用 QQ 测试小号，不直接使用主号。
- 只接 owner 私聊和一个明确白名单测试群。
- 首先运行只读影子模式：收事件、规范化、落短期 Journal，不回复。
- owner 未配置、配置冲突或身份无法解析时服务进入安全降级。
- 不保存 Cookie、token、模型密钥和真实 QQ 号到仓库。
- 建立攻击回放集，至少覆盖冒充主人、修改称呼、删除主人、跨用户套话、重复投毒、转发冒充和危险工具诱导。

## 建议的第一轮正式实现顺序

1. `InboundEvent` 与 OneBot 录制回放测试。
2. `Principal`、外部身份映射与 fail-closed owner guard。
3. Journal、保留期、去重和按主体删除。
4. Persona constitution/style 版本库与只读注入。
5. observation/candidate/quarantine/active/invalidated 记忆状态机。
6. Memory Control Plane。
7. 通过攻击测试后再启用受控回复。

- ADR-0002（分层可审计记忆）：建议接受。
- 真实 QQ 自动回复：尚未授权，也不应在 Phase 1 开启。
