# ADR-0001：自研窄核心，而非直接分叉整个 corlinman

- 状态：建议接受
- 日期：2026-07-22

## 背景

corlinman 已拥有 QQ、记忆、人格、工具、审批、后台与部署能力，直接分叉看似最快。但其上游截至快照已有 1222 个全引用提交、88 个标签和大量 Python/TypeScript 模块。我们的第一目标只有 QQ、身份权限、人格与可治理记忆，并且主人权限与抗投毒要求比上游兼容默认值更严格。

## 决策

新建规模可控的 Python 项目，借鉴 corlinman 的事件规范化、作用域记忆、召回账本、persona 分层、工具审批和运维面；必要时在遵守 MIT 许可证的前提下复用独立代码片段或测试思想。NapCat 作为独立依赖运行，不复制其代码。

## 理由

- 更容易理解每一条安全边界，适合作为个人长期维护和学习项目。
- 能把 owner fail-closed、记忆候选区与人格防火墙从第一天做成核心不变量。
- 避免为了四个核心能力同时维护上游的多通道、商城、QZone、多智能体等大面积功能。
- 后续仍可通过 OneBot、OpenAI-compatible、MCP/JSON Schema 等稳定接口扩展。

## 代价

- 初期不能立刻获得 corlinman 全部 UI 与部署能力。
- 需要自己完成基础工程、测试和后台。
- 必须持续跟踪 QQ 适配层变化。

## 何时重新评估

如果项目目标改为快速部署完整多通道平台，或开发人力增加到能长期跟踪上游，可评估维护一个薄分叉/插件；在此之前不建议整仓 fork。
