# ADR-0002：分层、可审计的记忆治理

- 状态：建议接受
- 日期：2026-07-22

## 背景

“把聊天切块后全部写入向量库”能快速做出演示，但会混淆对话证据、用户事实、任务承诺与人格身份，也很容易被群聊重复内容和提示注入污染。向量相似度无法回答谁有权写入、事实是否过时、来自谁、为何可信、如何删除和回滚。

## 决策

采用独立的 Journal 与 Memory Pipeline。原始消息只作为不可信 observation；候选记忆带来源、范围、类型、风险和置信度，经过规则或人工审核后才能 active。更新通过 invalidation + replacement 保留历史。检索使用作用域过滤后的 FTS5/BM25，并可叠加向量相似度；每次注入建立 recall ledger。

## 记忆类型

- `user_fact`：某人的稳定事实。
- `preference`：可变化的偏好与交互方式。
- `relationship`：称呼、熟悉度等关系状态。
- `commitment`：智能体或用户明确承诺的待办。
- `episode_summary`：一次事件的压缩摘要。
- `group_norm`：某群明确约定的规则。
- `self_core`：不进入自动提取，只能主人后台维护。

## 写入权限

- 普通聊天可产生前六类候选，但不能直接 active 高风险项。
- 任何聊天都不能写 `self_core`、owner 身份或角色权限。
- 群聊产生的个人事实默认只在该群范围可见，除非主人审核提升范围。
- 被引用/转发的文本不能作为原作者的直接证据。

## 后果

系统会比“全量向量化”多一些表和审核流程，但获得可解释、可删减、可恢复和抗投毒的基础。这是长期智能体可以安全成长的必要成本。
